# SilverChat

## Возможности

**Сообщения.** Текст, фото, видео, голосовые, видеокружки, файлы, стикеры,
GIF, геометки, контакты, опросы, подарки. Ответы, пересылка, реакции,
закрепы, редактирование и удаление, черновики, отложенная отправка, поиск по
сообщениям и глобальный поиск.

**Чаты.** Личные, группы до 200 000 участников и каналы. Роли и права,
медленные режимы, закреплённые сообщения, пригласительные ссылки, папки,
взаимные блокировки, скрытие последнего посещения.

**Звонки.** Голосовые и видео, WebRTC, медиа напрямую между устройствами.
Переключение камеры, громкой связи, блюра. История вызовов.

**Сторис.** Фото и видео до 60 секунд, подписчики и видимость, реакции,
счётчик просмотров, камера с сетками.

**Профиль.** Анимированные аватары и баннеры, биография со ссылками,
редактирование, удаление аккаунта.

**Экономика.** Валюта «сильвер», ежедневные стрики, кошелёк с журналом
операций, подарки, Premium-подписка.

**Маркетплейс.** Покупка и продажа юзернеймов: аукцион, мгновенная покупка,
резервирование, комиссия площадки, мои лоты.

**Администрирование.** Учётная запись `@silver`: права разработчика, выдача
Premium и верификации, управление пользователями, объявления на весь чат,
настройки сервера, статистика.

**Интерфейс.** Glassmorphism, тёмная и светлая темы, масштаб шрифта, отключение
анимаций, блокировка скриншотов, биометрическая блокировка, уведомления с
ответом прямо из шторки.

## Быстрый старт

Требуется JDK 17 и Android SDK с платформой 36 и build-tools 36.0.0.

```bash
# сборка debug-APK
./gradlew :app:assembleDebug

# установка на устройство
./gradlew :app:installDebug

# все тесты
./gradlew test

# статический анализ
./gradlew ktlintCheck lint detekt

# полная проверка перед пушем
./gradlew check
```

Приложение обращается к `https://api.silver.chat/v1/` и
`wss://api.silver.chat/v1/realtime`. Адреса переопределяются без правки кода:

```properties
# gradle.properties или local.properties
silverchat.versionName=0.1.0
silverchat.versionCode=1
# пины через запятую, формат sha256/<base64>; пустое значение — пиннинг выключен
silverchat.certPins=
```

## CI

GitHub Actions, два пайплайна.

### ci.yml — на каждый push и pull request

| Job | Что делает | Блокирует |
|---|---|---|
| `static-analysis` | `ktlintCheck`, `lintDebug`, `detekt`, артефакт с отчётами | ktlint и lint — да; detekt — `continue-on-error` |
| `build` | Матрица по группам модулей (`core`, `feature`, `app`): `assembleDebug` + `testDebugUnitTest` каждого модуля | да |
| `assemble-release` | Только на `main` и при ручном запуске: AAB, APK и `mapping.txt` | нет |
| `summary` | Сводка; падает, если `build` не зелёный | да |

`assemble-release` терпит отсутствие секретов: собирает unsigned-артефакт и
печатает `::warning`. Пиннинг сертификатов проверяется отдельно от подписи —
он нужен и в unsigned-сборке, потому что проверяет канал, а не авторство
артефакта.

### release.yml — по тегу `v*.*.*`

Версия берётся из тега, `versionCode` — из числа коммитов. Дальше: декодирование
keystore, подписанная сборка AAB + APK (подпись v3 и v4 включены в
`AndroidConfig`), проверка подписи через `apksigner`, создание GitHub Release
и выгрузка во внутреннее тестирование Play Store.

В отличие от CI, отсутствие `RELEASE_KEYSTORE_B64` здесь — ошибка сборки
(`::error` + `exit 1`): неподписанный релиз выпускать нельзя. Если
`CERT_PINS` не заданы, release собирается **без пиннинга**, а шаг печати
предупреждает: пиннинг включается только реальными значениями, потому что
подстановка заглушек делает приложение нерабочим.

### Секреты

| Секрет GitHub | Для чего |
|---|---|
| `RELEASE_KEYSTORE_B64` | Keystore в base64 |
| `RELEASE_KEYSTORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD` | Подпись |
| `CERT_PINS` | Пиннинг сертификатов, `sha256/<base64>` через запятую, минимум два |

Gradle читает их через переменные окружения `SILVERCHAT_*`
(`SILVERCHAT_KEYSTORE_PATH`, `SILVERCHAT_CERT_PINS`, …) либо через свойства
`silverchat.*` в `gradle.properties` — оба пути равноправны по приоритету:
сначала окружение, затем свойства, затем значение по умолчанию.

## Качество кода

| Инструмент | Статус |
|---|---|
| ktlint | блокирует CI (стиль `android_studio`, лимит 140 символов) |
| Android Lint | блокирует по явному списку `severity=error` |
| detekt | отчёт, порог — по измеренным максимумам кодовой базы |
| Модульные тесты | 67 проверок в `:core:common`, `:core:network`, `:core:data`: маппинг ошибок, декодер WebSocket, ключи идемпотентности. Остальные уровни пирамиды не покрыты |

Пороги сложности в detekt выбраны по фактическим максимумам, а не «на глаз»:
самый длинный файл — `SilverChatApi` с 148 эндпоинтами, самая длинная функция —
Compose-экран на 225 строк (Compose из правила исключён). Подробности и план
включения блокировки — в [ARCHITECTURE.md](ARCHITECTURE.md#качество-кода).

## Соглашения

- **Язык кодовой базы** — русский: комментарии, KDoc, строковые ресурсы,
  документация. Имена в коде — английские.
- **Один источник правды.** Версии — в `libs.versions.toml`, настройки
  Android — в `AndroidConfig.kt`, адреса — в `BuildConfig`, имена заголовков —
  в `HttpHeaders`, словарь операций — в `SocketOps`.
- **Ошибки как значения.** Публичные операции возвращают `ScResult<T>`;
  сетевые вызовы оборачиваются в `apiCall { }`, который понимает и статусы
  HTTP, и бизнес-коды сервера.
- **Отмена корутины пробрасывается.** `CancellationException` никогда не
  оборачивается в `ScError`.
- **Фичи изолированы.** Переход между фичами — только через маршрут из
  `:core:designsystem`, прямой зависимости между модулями фич нет.

## Статус

Клиент реализован полностью по описанному контракту. Сервер существует как
спецификация: `backend-contract/` описывает всё, что нужно для его
реализации, включая поведение, которое клиент проверяет в тестах.

Тестами покрыт только нижний уровень пирамиды: 67 проверок на маппинг ошибок
HTTP, декодирование кадров WebSocket и хранилище ключей идемпотентности — там,
где дефект молчалив и стоит денег или данных. Use case'ы, репозитории,
ViewModel и Compose-экраны тестов не имеют; инфраструктура для них готова
(фикстуры, правила диспетчеров, зависимости во всех модулях).

Известные пробелы — в разделе
[«Известные пробелы»](ARCHITECTURE.md#известные-пробелы) ARCHITECTURE.md.
